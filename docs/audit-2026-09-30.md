## 2. P0: fix before the next real run

## 3. P1: correctness and quality

Planning and reports
- `make_plan` crashes if the model returns valid JSON that is not an object; a string `sub_questions` becomes letters. [R]
- Revision requests that remove things ("drop the history of RAG") are turned into additions; very short topics ("add AI") are ignored. [R]
- After 2 revisions the third plan runs without being shown; a plain-text resume counts as approval. [C]
- `clarify` re-runs on resume: an extra model call, and if it returns no questions the user's answers are dropped. [P]
- The executive summary is not validated (invented `[E99]` survives; its citations miss the appendix). [R] The Limitations line always says "nothing was searched on the web", false when fetching ran. [R]
- The judge sees attacker-controlled text and can be instructed by it; quotes are not length-capped; claims can carry links or images into the report. The "checked twice" wording overstates the guarantee. [C]
- `collect` throws away the ingest result, so "saved N" can be shown when nothing was indexed. [C]

Ingest and fetcher
- Files that convert to zero chunks, or fail, are retried on every run (up to 77 s each, and auto-ingest runs at the start of every run). [C]
- Two folders with the same name prune each other (namespace is the folder name). [C]
- No WAL or busy timeout; connections are opened per node and never closed; the cached search matrix can go stale and crash `search`; concurrent host and container ingest can hit "database is locked". [C]/[P]
- Seed PDFs with the same filename on different hosts, and pages differing only by query string, are treated as duplicates. [R]
- Europe PMC record with a null title crashes the whole collect; an arXiv error feed becomes a candidate. [R]
- Fetch index written only at the end, non-atomically; a torn file breaks every later run. [C]
- arXiv API and PDF hosts have separate 3-second buckets. [C]

Dashboard
- Run id is kept per tab (`sessionStorage`), thread id per browser (`localStorage`): a new tab or browser restart shows a frozen snapshot of a still-running run. [R]
- A dead run shows "Extracting evidence..." forever; there is no cancel button, so "start a new goal" leaves the old run burning the GPU; a failed first run locks the form and clears what you typed. [C]
- Arriving with `?topic=` forgets the remembered thread on every refresh. [C]
- Knowledge-graph route re-embeds every note on every request, and an Ollama error shows "No research notes yet". History page 500s if one note has bad YAML. [C]
- No double-submit guard on Continue/Approve/Revise. [C]

Quick assistant (original code)
- **0% automated coverage** (`graph.py`, `utils.py`, `lmstudio.py`, `prompts.py`, `state.py`). The debate removal was verified only by a live run.
- `graph.py` discards the result of stripping thinking tokens (thinking-model JSON falls back to a generic query) and crashes on list JSON. `plan_research` ignores `llm_provider=lmstudio`. [C]
- `max_web_research_loops=1` runs two search passes (off by one, inherited). [R]
- `requests.post` in the Perplexity helper has no timeout. [R via lint]
- The profile grows without limit and is injected in full into every prompt. [P]

## 4. P2: config, docs, ops, hygiene

- **Empty env vars override per-run settings** (`PLANNER_MODEL=""` from compose beats a per-run value). [R] Treat empty as unset.
- Runbook errors: `--md-out` inside an indexed folder indexes every page twice [R]; `DOCS_DIR` is not indexed by deep research (only the quick assistant); "under 2" should be "under 3"; `CONTACT_EMAIL`, `KB_PATH`, `LIBRARY_FOLDERS` are not forwarded by compose. [C]
- `.env.example` is missing about 20 real settings and has a misleading comment; `LOCAL_LLM` default differs from the code. [C]
- Stale docs: README test and layout sections, scripts list; DECISIONS references (`BENCHMARKS #3`, Sources-only); EVALS "temperature 0.2" and section 1's command now reproduces the 77-document numbers; `from_runnable_config` docstring does not contain the precedence rule DECISIONS says it does; build-plan names a `collector.py` that is `fetcher.py`. [C]
- Dockerfile: layer order defeats the cache, no `uv.lock`, Docling needs `libgl1`/`libglib2.0-0`, Docling weights download from Hugging Face (contradicts "nothing leaves the machine"), no healthcheck. [C]/[P]
- CI: never import-checks `goal_graph`; mypy declared but never run; two inconsistent dev dependency groups.
- Repo: **56 uncommitted changes**, and many new files are untracked, so CI and the Docker job would fail on a fresh checkout; `.coverage`, `.kb/` should be ignored. The removed debate feature still exists in git history (commits `91577e8`, `7226bdc`, `11aebfc` and HEAD until the removal is committed).
- Scripts: `acceptance_lean.py` and the walkthrough read report paths from the host (fail against Docker); several default to cwd-relative paths; `--md-out` flattens same-named files.
- Tests: the fake judge answers "supported" to everything (no test that an unsupported claim is dropped); no tests for config precedence, `default_kb_path`, the feedback route, SSRF, oversize responses, embedding-dimension change or concurrency; one test pins questionable behaviour.

## 5. P3: minor
Page numbers are wrong for most chunks; `SKIP_SECTIONS` also drops headings like "Cross-references in practice"; `SKIP_DIRS` silently skips any user folder called `raw`; 5 tiny chunks under 40 characters; JATS lists and figures dropped; Sources links break on titles containing `]`; profile "append" inserts at the top; markdown images in reports are fetched by the browser on view (exfiltration channel); LangSmith lookups have no timeout; some accessibility gaps (live regions, keyboard access to the graph, `aria-current`); stale entries in the fetch index (6 point at deleted files, handled lazily); mobile nav omits two pages.
